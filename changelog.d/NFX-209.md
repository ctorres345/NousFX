### Review loop
- `testfail.py run` uses a matching `run-check --stamp` pass to cut a suite run (NFX-209). With a stamp for the same tree, branch and check (matched the way `--mark` matches it: the gate's `stamp_fields` and signed `valid_stamp`; left in place for `--mark`), the restored run goes first. When it passes, the verdict is `no` after one run instead of two. When it fails, the with-change run still runs in the clone after it, since that run is the clone's `baseline-fail` check and the passing log that failure names are filtered against; the stamp's pass ran in the working tree and kept no log, so a `yes` never rests on it. A `  with change:` line in `run` and `attest` says which happened. No stamp, a stale or forged one, another branch or another command: both runs as before.
