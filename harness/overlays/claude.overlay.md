## Claude Code
- A missing tool is not a stop: load it with `ToolSearch` and continue. Report a blocker only after the obvious fix failed, and name what you tried.
- Lookups (Haiku): `Explore` for code search, `researcher` for docs and APIs, `test-runner` for noisy build or test output. Prefer these over the cavecrew/caveman-explore skills.
- When the work is done, ask the user once whether to open the PR. On a yes, run the `review-loop` skill yourself, then `gh pr create`. The `review-gate.py` hook blocks the PR until a review is recorded; if blocked, run the loop instead of working around it. Skip only with the user's explicit approval.
- Any request to review, critique, polish or optimize UI/UX, design, responsiveness or accessibility: invoke the `ui-review` skill first, in any project. Run it once on finished UI work, before asking about the PR.
- Token hygiene: do not Read whole files over ~20K chars (Grep, offset/limit, or `Explore`), never Read old transcripts under `~/.claude/projects`, and do not re-read unchanged files. Send long build or test output to a file; read the tail.
- One task per session. When a task is done, the topic changes, or context is large, say so in one line and offer `/handoff` then `/clear`. Use `/compact focus on <topic>` at milestones.
- Handoff (every project): before any planning or edits on a session's first task, read `.claude/handoff.md` (or a root `HANDOFF.md`) if it exists, even if the user did not mention it or it seems unrelated, then check it against `git status` and the branch. Do not wait to be asked. Treat its "Suggested skills" as part of the plan: invoke each model-invocable one at the step it names, or say in one line why it does not apply; name the user-only ones for the user to type. If it is missing, say nothing.
- Fable is a premium resource (limited weekly allowance). `architect` and `reviewer-deep` are the Fable agents, both read-only. When a task fits one, say so in one short line (why, and what it would look at) and ask. At the start of a `fable-review` ticket, offer `architect` to check the plan. Run it only after a clear yes, then summarize the result for the user to decide. Never in unattended `/goal` runs.
- Work based on an approved prototype or design (artifact, Figma, mockup): the prototype is the spec; use the `prototype-fidelity` skill.
