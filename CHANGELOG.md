# Changelog

## 1.3.0 (unreleased)

### Via
- The prototype page is easier to compare and to read (NFX-82). At 700 px and narrower each finding gets a CSS-only Before/After switch (After selected) so you no longer scroll past two 844 px frames; the spec panel highlights the Light or Dark column for the selected theme (bolder header too, not colour alone); the "Jump to finding" list is plain underlined links, no longer styled like the variant tabs; the toggle is named "Mockup theme"; the before image's alt names the screen, theme and issue. `audit.md` and `prototype.md` tell variant authors to redraw the whole screen, not one element in an empty frame.

## 1.2.0 (unreleased)

### Skills
- Via runs `break-ui`, `emil-design-eng` and `review-animations` when their work comes up: `platforms.md` lists each in the Web and the Compose and Flutter Skills tables with a when-to-run rule, and a new `platform-skills` eval case checks the rows (NFX-124).
- New `local-assist` skill: `local_summary.py -- <cmd>` runs a build or test command and, on failure, has the Ollama model on my PC (`[local_assist]` `url` and `model` in `local.toml`) summarize the log in at most 120 words. It only talks to loopback or private addresses, ignores proxy variables and redirects, and on any problem prints `local-assist unavailable: <reason>` and exits 3, which means run `test-runner` instead (NFX-142).

### Tickets
- Done is now written as proofs. Every acceptance criterion in the ticket template ends in a `Proof:` line (a command, or `manual: <step>`), and a new Failure modes section says how the work could break and what it does then. The jira-sync ready check flags a `ready-for-agent` ticket that lacks either, and the PR template has an "Acceptance criterion, proof, result" table. The template has one source (the `project-setup` asset), and `scripts/test_ticket_template_single_copy.py` fails when `docs/agents/ticket-template.md` drifts from it (NFX-104).
- The jira-sync audit warns when a `Proof:` command names a repo path that does not exist (`proof-path:<KEY>`, medium). It checks `ready-for-agent` tickets (a draft may name a file it will create), skips `manual:` proofs, flags, globs, URLs, git refs, redirects, `cd` commands and absolute or `~` paths, and never fails the ready check, so a false positive costs a warning, not a blocked ticket (NFX-140).

### Review gate
- review-loop runs the security skills the diff calls for. `tier.py` prints a new `security` list: `agentic-actions-auditor` for a path under `.github/workflows/` (a deleted one too), `sharp-edges` for a whole-word security keyword (auth, crypto, token, secret, session, cookie, csrf, cors, tls) in a code file's path or changed lines. The main thread runs each once on the first round (`references/security.md`, shipped to projects); findings are `S1..`, verified like a `high` and counted in `--findings`. `security-audit` stays on request only. SKILL.md's size cap is now 14,900 bytes (NFX-124).
- A commit on the wrong branch is caught where it happens. The subject must start with the branch's Jira key (`NFX-86: x`, or `NFX-85, NFX-86: x`). Locally, a new advisory `claude/githooks/commit-msg` and the Claude hook (on a literal `git commit -m`) warn and never block. In CI, a new step runs the base gate's `check-commits`, which fails a PR with a commit that names another key or none; merge commits and subjects git writes itself (`Merge`, `Revert`, `fixup!`, `squash!`) are skipped, and a base gate without `check-commits` only warns (NFX-86).
- When the gate blocks a PR create for a missing `Review-Gate:` line, its message now also names the repo's PR template: `.github/pull_request_template.md`, else `claude/templates/pull_request_template.md`, and nothing when neither exists, because the gate runs in every repo. The review-loop skill now shows `--labels env-none,size-S`: the labels are one comma-separated argument, and a space-separated list fails (NFX-135).
- `prove.py` (in the review-loop skill) runs the `Proof:` lines of a ticket's acceptance criteria and stamps them. `attest` then prints `AC-Proof: n/n manual:m <tree> <sha>`, so a `/goal` condition can name one line. The sha covers the normalized proofs, a malformed `Proof:` line is refused, a proof that edits files writes no stamp, and the stamp is signed with the pass stamp's key and its own `kind`. The gate's stamp helpers take a file name for this, and `claude-proof-pass` is on the deny list with the other gate files. Proofs are self-asserted: CI does not re-run them (NFX-105).
- `review-loop` gives every finding a disposition (`fix-now`, `follow-up` or `note`, and a note needs a reason), runs one delta round on the fixed lows (the reviewer sees only the fix diff, and the full suite still runs), asks the reviewer to flag a `Proof:` that cannot fail, and prints a per-finding table with a disposition column. `docs/review-gate.md` holds a `/goal` condition template built on the `AC-Proof` line.
- `review-loop` loads less on every review: its Gemini checks and Fable offers moved to `references/gemini.md` and `references/fable.md`, word for word, with a short stub left under each heading that says when to read the file. `SKILL.md` went from 20.3 KB to under 14.5 KB. Project copies (`nousfx_project.py`) ship both references too (NFX-114).

- In a cloud session the project hook no longer runs the branch's own copy of the review gate. It reads the gate from the default branch, runs it with `python3 -I -B`, and that gate blocks a PR create when the repo's gate or parser copy differs from main's ("the gate copy differs from main"). When `origin` has not been fetched it blocks a PR create with "fetch origin first". Sync adds a note to a repo whose hook still runs its copy directly. CI and the protected `main` stay the real check (NFX-107).
- On Windows a check that times out is stopped with its whole process tree (NFX-115). `run_check` ran `proc.kill()`, which ended only `cmd.exe`, so a Gradle daemon or test runner could keep editing files after the tree comparison. It now runs `taskkill /T /F /PID <pid>`; if `taskkill` is missing, hangs or fails, it falls back to `proc.kill()` and the failure message says only the shell was stopped. A timeout never passes, so a child that outlives `taskkill` still refuses the mark. POSIX is unchanged (process group kill). Only timeouts are covered: on Windows, children left behind by a check that exits on time are still not stopped. Not confirmed on a real Windows machine yet (the manual AC).
- The gate closes two low gaps in how it reads a command run by an unknown program (NFX-123, left by the NFX-120 review). A shell named in an assignment (`SH=bash; $SH $OPTS "$(cat c.txt)" name`, `X=sh; Y=-c; ...`) or as `$SHELL`/`${SHELL}` now counts as a shell, and a `$(...)` or backtick in any word after the variable counts, not only in the first one. All of them block as a possible `gh pr create`; the adb forms (`A=adb; D="-s X"; $A $D shell ...`) still pass.
- CI accepts a `skipped:` review attestation only with a `review-skip` label last applied by the repo owner or an org member (NFX-110). The attestation step reads the PR's events with `gh api` (the workflow gets `issues: read`) and fails closed: no label, unreadable events, a bot or a stranger all fail. The PR's `author_association` does not count, since it says who opened the PR, not who labeled it. Create the label once with `gh label create review-skip`.
- One default-branch rule for the gate and `tier.py` (NFX-108). It lives in a new `claude/hooks/git_refs.py` instead of two copies, and `tier.py` has a `--base-ref BRANCH` flag: `risk_paths` and the merge base come from `origin/BRANCH`, and a missing branch is Tier 2 with the reason. CI passes the PR base, so a stacked PR no longer reads `origin/HEAD`; a base whose `tier.py` has no flag yet runs as before with a warning. Locally `origin/HEAD` is trusted as `git remote set-head origin -a` set it, and CI is the control. `--mark` refuses when `git_refs.py` is missing next to the gate. Re-run the sync (`python3 -B scripts/nousfx_sync.py --tools claude`, then `--project` per repo) so the new file is installed; in a repo with cloud sessions, merge the refreshed `.claude/hooks/git_refs.py` and the review-gate hook from `project-setup` to the default branch.
- A screenshots branch can be pushed. In a project with the pre-push hook, `<prefix>/<KEY>-shots` was blocked (not `<prefix>/<KEY>`, no review mark), so PR screenshots could not go up. A new `review-gate.py check-shots` passes such a branch only when it is named right and every commit on it (at most 100, no merge) changes only regular media files under `shots/<KEY>/` (subfolders such as `light/` are fine); the hook asks it first for any `-shots` branch, passes only on exit 0 plus the gate's success line, and prints the gate's reason when it falls through to the normal check. Re-run the sync (`nousfx_sync.py --tools claude`, and `--project` per repo) to get the new gate and hook (NFX-143).

The ratchet keeps 50 bytes of room, its failure message points to a skill before a cut, and "from docs and config" is back in the runbook line (NFX-133).

Under 100 changed lines (insertions plus deletions, tests excluded, untracked files counted) it does the four checks inline, applies the fixes and prints `Step 0 inline: N changed lines`; 100 or more still invokes `simplify`. The count ignores the risk tier, and the loop's reviewer still sees the final code (NFX-139).

The delta round and the post-Argon fix no longer run their own suite, and the reviewer gets "last full run, or not run this round" (NFX-138).

## 1.1.0 (2026-11-09)

### Review gate
- The branch rule follows my prefix. The gate reads `[branch] prefix` from `~/.config/nousfx/local.toml` and allows only `<prefix>/<KEY>`; with no usable prefix (cloud, CI, a fresh install, a broken file, Python < 3.11) it checks the shape `[a-z0-9-]+/<KEY>` and never blocks on the config. CI runs the base gate's new `check-branch` on the PR branch; the `branch-exception` label skips it for an OWNER or MEMBER author, and a base gate without `check-branch` only warns. The jira-sync audit counts any `<prefix>/<KEY>` branch (not `-shots`) and names it. The shared rules say exceptions are my call (NFX-119).
- The gate no longer passes by being slow or by a common alternative command. Sync writes one budget into every gate hook (`--budget 55`, timeout 60) and the gate blocks with "gate timed out; retry or review at Tier 3" when it runs out; each tree is hashed once per run; a payload it cannot read blocks unless the tool cannot open a PR; and `gh api`, `curl` and `wget` PR creates (plus a GraphQL `createPullRequest`) block, while GETs pass (NFX-102).
- An agent can no longer waive its own review as easily. Sync denies Claude's file tools the gate's marker, pass stamp, stamp key and branch-name exception (by name, in any git dir; `deny.toml` cannot drop these), adds `ask` rules for `review-gate.py --skip`, `--tier-override` and `--allow-branch`, and the gate's messages say to ask me instead of printing a waiver command (NFX-101).
- `gh pr create` (and a create-PR MCP tool) now also needs a `Review-Gate: <HEAD tree>` line in the PR body. No body, `--fill`, a stale hash, a body built at run time or a body file without the line blocks, and the message prints the exact lines to paste. `attest` refuses with "commit or clean first" when the working tree differs from HEAD (NFX-85).
- The tests no longer run twice before a PR. review-loop's last test run is `review-gate.py run-check --stamp`, which writes a signed pass stamp for the tree; `--mark` on the same tree, branch and command uses it instead of running the check again. Any changed file still forces a run. `scripts/run_checks.py` runs the suites in parallel (`-j N`, `-j 1` for one by one). A root `HANDOFF.md` is gitignored, and `via.example.json` lists `obsidian.argon_log` (NFX-97).
- Device scripts that run a program through variables (`$ADB $DEV shell ...`) no longer block as a PR create. A program path that ends in a plain file name other than gh (`$S/inst.sh`) is not gh. Otherwise an argument variable before `pr` no longer counts as a possible create when a plain word that is not a flag's value follows it (`shell`), since `gh pr create` takes none; it still counts when the command (read with quotes and escapes removed) names `gh` or a shell, has `pr` and `create` or `new`, or runs a command substitution there, and a word that may vanish (`{,}`, a glob) proves nothing. `$GH pr create`, `$GH pr $SUB`, `SUB="pr create"; $GH $SUB` and `SUB=$(cat a); $GH $SUB` still block. Still a false block: a variable followed only by flags (`"$EMU" $EMU_ARGS -avd Pixel_7`) (NFX-120).

## 1.0.0 (2026-11-09)

The daily-use harness: Claude Code and agy on Mac and Windows, one sync command, a gate that runs the tests, trimmed rules, and a review loop that scales with risk. Proven on Animus.

### Sync and install
- One command, `scripts/nousfx_sync.py`, writes the global rules, agents, skills, hooks and MCP servers for Claude Code and agy, with a dry run, a drift check and a restore (NFX-29, 30, 35, 38, 41, 42).
- Project mode sets up one repo for every tool (NFX-46). Animus is migrated (NFX-47).
- Outside skills are pinned by commit and checksum in `harness/skills.lock.json` and fetched by sync (NFX-55).
- A session-start warning tells me when this machine is behind `main` (NFX-57).
- `install.sh` (Mac) and `install.ps1` (Windows) are now thin wrappers: dry run, confirm, then the sync (NFX-48). Two behaviors of the old installer are gone: it no longer writes through a symlinked `settings.json` (the sync stops and asks me to replace the link with a file), and `CLAUDE_HOME` is ignored (use `--home`).

### Rules
- The always-loaded rules shrank from about 9 KB to 4 KB, with one copy of each rule (NFX-58).

### Review gate
- The gate runs the project's check command before it records a review (NFX-54).
- An agy adapter blocks `gh pr create` without a review (NFX-44).
- `--mark --tier N` runs `tier.py` and refuses a lower tier unless I give a reason (NFX-68).

### Review loop
- `tier.py` picks a review tier from the diff and the ticket labels (NFX-62).
- Reviewers by tier: `reviewer-light`, `reviewer`, `reviewer-high`; the PR body gets a `Review-Tier:` line (NFX-63).
- Findings carry a confidence score, and every high is verified before it is fixed or rejected (NFX-65).
- Fable (`architect`, `reviewer-deep`) is offered only where it pays off, and only after I say yes (NFX-66).
- Gemini checks run inside the loop: Argon on UI changes, a code check on Tier 3, only for allow-listed projects (NFX-64).
- The Gemini scripts run on Windows (NFX-56).

### Docs and templates
- A runbook with a smoke-check table, updated README and sync docs (NFX-48).
- The PR template has a "What I checked myself" section (NFX-48).
- The planned `mandy` plugin is dropped from the roadmap.

### Not in 1.0
- OpenCode (NFX-50, NFX-43), a lean profile (NFX-45) and the cross-tool eval (NFX-49).
- Live checks on a real Mac session and on Windows are tracked in NFX-53.
