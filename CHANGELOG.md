### Rules
- A retro at the end of every wave and solo ticket (NFX-192). `after-merge` has a new step 5 between the report and `/handoff`: it reads the pinned `retro` skill as a file (never edited; a missing file is reported and skipped) and follows it with the extras in `claude/skills/after-merge/references/retro.md`. A ticket with a brief or result file in `~/Releases/<project>/waves/<date>/` runs the retro only when every ticket with a `<KEY>.brief.md` or `<KEY>.md` there is closed in Jira (Done, Won't Do or Cancelled), over the whole wave, and otherwise names the open tickets; a `retro.md` written first claims the run, so it runs once; a ticket with no wave file is a wave of one. Unattended runs skip it. The extras: a mistake class counts once it has happened twice; fix order is API or structure, types, a check, a test, prose last; each proposed check fails on a real past instance and says how we tell it worked. Filing needs Cesar's yes per finding, at most 3 tickets per retro, labels `needs-triage` and `agent-filed` (never `ready-for-agent`), and a duplicate search that comments on a match. The four reviewer prompts allow one optional `habit:` line after the findings, never after `NO FINDINGS`. review-loop does not count it as a finding and lists it in the PR body under Habits, where the retro reads it; its SKILL.md cap goes from 16200 to 16300 for that clause. `scripts/test_retro_step.py` checks the text.
- Decision log and end-of-session report (NFX-191). `session_report.py decide` (in the `review-loop` skill's `scripts/`) appends a decision, its why, the rejected alternative and a lesson to `decisions.jsonl` under `~/Releases/<project>/reports/<date>-<name>/`; `render` writes `report.md` with what shipped, a decisions table, one-way doors held for Cesar, what was not verified and what to learn. Three ideas come from the pstack plugin's show-me-your-work skill (MIT, github.com/cursor/plugins/tree/main/pstack/skills/show-me-your-work): every entry carries an `evidence` pointer (a SHA, #PR, file:line or URL, never prose) and a `result`; the log is append-only, so a wrong entry is corrected by a new one with `--supersedes ID` and `decide` has no edit or delete (a correction keeps a held door unless it gives its own `--held`); and `render` warns when a SHA or path does not resolve. A blank why, evidence or result, prose evidence, a bad ticket key, a secret-shaped value or a root inside a git checkout exits 2 with nothing written; `NOUSFX_REPORT_ROOT` moves the root for tests. One pointer bullet sits in the Claude overlay ("Log decisions as made", so the log is written while working; shared rules 3863 bytes, `CLAUDE_RULES_BUDGET` 3846 to 3913), one in `review-loop` and one in `after-merge`.
- Waves get one fresh session per ticket (NFX-186). `harness/AGENTS.md` has one pointer line for both tools; the `handoff` skill holds the three cases (cloud project threads, terminal or desktop, Mac-bound tickets). "One task per session." left the Claude overlay so the rule lives in one place, and `CLAUDE_RULES_BUDGET` is reset to 3846 (the shared rules' 3796 bytes + 50).

## 1.3.0 (2026-11-15)

### Docs
- Meet Via (NFX-25). The README has a "Meet Via" section: a three-command quickstart, an example run on `samples/web` with screenshots, the config table and what Via does when an integration is missing. `CONTRIBUTING.md` has a skill-writing checklist. `scripts/fresh_user_test.py` installs Via from the marketplace in a temp HOME, and `docs/fresh-user-test.md` records the run: the install and the `via_setup.py` doctor passed (as scripts, not through Claude), the first capture on a new browser profile timed out, and `/via audit` inside Claude Code was not run. `scripts/test_readme_quickstart.py` checks the README commands, links and config keys.

### Review gate
- A PR that touches UI cannot be opened until `/via check` passed on the code (NFX-20). The gate reads `tier.py`'s `ui` flag and, for a UI diff, the `via-check-ok` record that `via_run.py pass` writes: it must be for the current code with `findings_open` exactly 0, and `pending_human` passes with a note. An unreadable diff, a `tier.py` error or timeout, or a `fallback` result blocks, with the error named. `--via-skip "<reason>"` records a skip (never unattended, never a secret-shaped reason); `attest` prints a `Via-Check:` line, and CI's new `verify-via` checks it, accepting a skip only with the `via-skip` label. `tier.py` results carry a `fallback` key, and the Via files are on the deny list with `--via-skip` an ask rule. A repo with no `origin/main` blocks a PR create now, because the gate cannot tell whether the diff is UI. The base branch needs `verify-via` before CI can verify this PR, so I merge it by hand.
- CI's Via check lets a skip line win over a plain line (NFX-145). `verify-via` used to print "Via check verified." on the first plain `Via-Check: <tree>` line it met, so a skip line next to it, in the PR body or the last commit message, never reached the `via-skip` label check. It now reads every line in both texts and prints the skip when there is one; a plain line alone still verifies. Paste only the `attest` output, so a stale skip line does not ask for the label next to a real pass.
- A skip label must be applied after the last push (NFX-147). CI used to keep a `review-skip` or `via-skip` waiver on the PR after a push, so an old approval covered new code. A shared `skip_label_ok` step now needs the label's last event for that label to be `labeled` by the owner or an org member and strictly newer than the push. GitHub has no server push time, so the push is the earliest review-gate run for the head SHA and PR, not older than the last force-push event (a committer date can be forged). Anything unreadable, a removed label or no matching run fails. The workflow needs `actions: read`, and a push needs the label applied again, even with the same tree.

### Via
- A slow first browser launch no longer stops `/via audit` (NFX-148). The first shot of a capture may wait up to 120 s beyond `VIA_SHOT_TIMEOUT` (180 s in all by default) and prints "The first launch is slow" on stderr while it waits; later shots keep the base limit, and a browser that never answers still exits 4 with its helper processes killed. `audit.md` runs the capture in the background, and SIGTERM or SIGHUP now kill the browser and clean up before exit 4. The README row and the fresh-user report no longer tell the user to rerun by hand.
- `/via check` has a pending-human state (NFX-111). In an unattended run, a medium finding that is routed and not an accessibility finding counts as `pending_human` instead of `findings_open`, so the check can pass while a person still decides. High, accessibility and unrouted findings stay open, and attended runs are unchanged. `pass` records `pending_human` and `pending_ids`; an attended pass prints the earlier ones as `earlier_pending`. The review gate still reads only `findings_open`.
- The prototype page is easier to compare and to read (NFX-82). At 700 px and narrower each finding gets a CSS-only Before/After switch (After selected) so you no longer scroll past two 844 px frames; the spec panel highlights the Light or Dark column for the selected theme (bolder header too, not colour alone); the "Jump to finding" list is plain underlined links, no longer styled like the variant tabs; the toggle is named "Mockup theme"; the before image's alt names the screen, theme and issue. `audit.md` and `prototype.md` tell variant authors to redraw the whole screen, not one element in an empty frame.
- The prototype page tells screen readers which variant is showing: each variant carries its own tab row with `aria-current="true"` on its own tab, still with no script. Choosing a tab moves focus to the variant that appears, so screen readers announce it. The focus ring on the selected theme segment is now white on the dark fill (about 17:1, was 2.5:1); a test checks both ratios (NFX-81).

## 1.2.0 (2026-11-13)

### Skills
- Via runs `break-ui`, `emil-design-eng` and `review-animations` when their work comes up: `platforms.md` lists each in the Web and the Compose and Flutter Skills tables with a when-to-run rule, and a new `platform-skills` eval case checks the rows (NFX-124).

It only talks to loopback or private addresses, ignores proxy variables and redirects, and on any problem prints `local-assist unavailable: <reason>` and exits 3, which means run `test-runner` instead (NFX-142).

### Tickets
- Done is now written as proofs. Every acceptance criterion in the ticket template ends in a `Proof:` line (a command, or `manual: <step>`), and a new Failure modes section says how the work could break and what it does then. The jira-sync ready check flags a `ready-for-agent` ticket that lacks either, and the PR template has an "Acceptance criterion, proof, result" table. The template has one source (the `project-setup` asset), and `scripts/test_ticket_template_single_copy.py` fails when `docs/agents/ticket-template.md` drifts from it (NFX-104).
- The jira-sync audit warns when a `Proof:` command names a repo path that does not exist (`proof-path:<KEY>`, medium). It checks `ready-for-agent` tickets (a draft may name a file it will create), skips `manual:` proofs, flags, globs, URLs, git refs, redirects, `cd` commands and absolute or `~` paths, and never fails the ready check, so a false positive costs a warning, not a blocked ticket (NFX-140).

### Review gate
- review-loop runs the security skills the diff calls for. `tier.py` prints a new `security` list: `agentic-actions-auditor` for a path under `.github/workflows/` (a deleted one too), `sharp-edges` for a whole-word security keyword (auth, crypto, token, secret, session, cookie, csrf, cors, tls) in a code file's path or changed lines. The main thread runs each once on the first round (`references/security.md`, shipped to projects); findings are `S1..`, verified like a `high` and counted in `--findings`. `security-audit` stays on request only. SKILL.md's size cap is now 14,900 bytes (NFX-124).
- A commit on the wrong branch is caught where it happens. The subject must start with the branch's Jira key (`NFX-86: x`, or `NFX-85, NFX-86: x`). Locally, a new advisory `claude/githooks/commit-msg` and the Claude hook (on a literal `git commit -m`) warn and never block. In CI, a new step runs the base gate's `check-commits`, which fails a PR with a commit that names another key or none; merge commits and subjects git writes itself (`Merge`, `Revert`, `fixup!`, `squash!`) are skipped, and a base gate without `check-commits` only warns (NFX-86).
- When the gate blocks a PR create for a missing `Review-Gate:` line, its message now also names the repo's PR template: `.github/pull_request_template.md`, else `claude/templates/pull_request_template.md`, and nothing when neither exists, because the gate runs in every repo. The review-loop skill now shows `--labels env-none,size-S`: the labels are one comma-separated argument, and a space-separated list fails (NFX-135).
- `prove.py` (in the review-loop skill) runs the `Proof:` lines of a ticket's acceptance criteria and stamps them. `attest` then prints `AC-Proof: n/n manual:m <tree> <sha>`, so a `/goal` condition can name one line. The sha covers the normalized proofs, a malformed `Proof:` line is refused, a proof that edits files writes no stamp, and the stamp is signed with the pass stamp's key and its own `kind`. The gate's stamp helpers take a file name for this, and `claude-proof-pass` is on the deny list with the other gate files. Proofs are self-asserted: CI does not re-run them (NFX-105).
- `review-loop` gives every finding a disposition (`fix-now`, `follow-up` or `note`, and a note needs a reason), runs one delta round on the fixed lows (the reviewer sees only the fix diff, and the full suite still runs), asks the reviewer to flag a `Proof:` that cannot fail, and prints a per-finding table with a disposition column. `docs/review-gate.md` holds a `/goal` condition template built on the `AC-Proof` line.
- `review-loop` loads less on every review: its Gemini checks and Fable offers moved to `references/gemini.md` and `references/fable.md`, word for word, with a short stub left under each heading that says when to read the file. `SKILL.md` went from 20.3 KB to under 14.5 KB. Project copies (`nousfx_project.py`) ship both references too (NFX-114).

- In a cloud session the project hook no longer runs the branch's own copy of the review gate. It reads the gate from the default branch, runs it with `python3 -I -B`, and that gate blocks a PR create when the repo's gate or parser copy differs from main's ("the gate copy differs from main"). When `origin` has not been fetched it blocks a PR create with "fetch origin first". Sync adds a note to a repo whose hook still runs its copy directly. CI and the protected `main` stay the real check (NFX-107).
- On Windows a check that times out is stopped with its whole process tree (NFX-115). `run_check` ran `proc.kill()`, which ended only `cmd.exe`, so a Gradle daemon or test runner could keep editing files after the tree comparison. It now runs `taskkill /T /F /PID <pid>`; if `taskkill` is missing, hangs or fails, it falls back to `proc.kill()` and the failure message says only the shell was stopped. A timeout never passes, so a child that outlives `taskkill` still refuses the mark. POSIX is unchanged (process group kill). Only timeouts are covered: on Windows, children left behind by a check that exits on time are still not stopped. Not confirmed on a real Windows machine yet (the manual AC).
- The gate closes two low gaps in how it reads a command run by an unknown program (NFX-123, left by the NFX-120 review). A shell named in an assignment (`SH=bash; $SH $OPTS "$(cat c.txt)" name`, `X=sh; Y=-c; ...`) or as `$SHELL`/`${SHELL}` now counts as a shell, and a `$(...)` or backtick in any word after the variable counts, not only in the first one. All of them block as a possible `gh pr create`; the adb forms (`A=adb; D="-s X"; $A $D shell ...`) still pass.
- CI accepts a `skipped:` review attestation only with a `review-skip` label last applied by the repo owner or an org member (NFX-110). The attestation step reads the PR's events with `gh api` (the workflow gets `issues: read`) and fails closed: no label, unreadable events, a bot or a stranger all fail. The PR's `author_association` does not count, since it says who opened the PR, not who labeled it. Create the label once with `gh label create review-skip`.
- One default-branch rule for the gate and `tier.py` (NFX-108).
